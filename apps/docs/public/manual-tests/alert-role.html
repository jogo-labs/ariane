ar-alert : le rôle est-il pris en compte par le lecteur d'écran ?

Chargement du bundle…

Mode d'emploi
  1. Cette page charge le composant tel que construit pour ce déploiement (bundle indiqué ci-dessus).
  2. Le composant écrit lui-même l'attribut role selon variant, sauf si l'application en a déjà posé un (avant ou après l'insertion) : dans ce cas il n'y touche plus. Pour comparer avec la version publiée alpha.14 (qui écrase un role posé par l'application), ouvrir la page avec ?bundle=https://unpkg.com/@ariane-ui/core@0.1.0-alpha.14/cdn/index.js.
  3. Lecteurs d'écran à essayer : VoiceOver (Safari, Chrome), NVDA (Firefox, Chrome), JAWS si disponible. Un écart est connu entre Safari et Chrome avec VoiceOver : tester les deux. Écouter pour chaque scénario et reporter le résultat en bas de page. Les scénarios A demandent de recharger la page avec le lecteur d'écran actif.
  4. Vérification dans l'outil de développement : l'attribut role de chaque ar-alert est visible dans l'inspecteur du DOM (et dans le tableau ci-dessous, mis à jour en direct) ; l'onglet « Accessibilité » de Chrome donne le rôle calculé. Une alerte error doit être alert, une info doit être status.

Les blocs en pointillés sont des témoins natifs (un <div role="…"> ordinaire) : si le lecteur d'écran ne les annonce pas non plus, le silence ne vient pas du composant.

A. Alertes présentes au chargement (relancer la page avec le lecteur d'écran actif)

Rôle attendu : error et warning donnent alert, success et info donnent status, écrit par le composant. Un role posé par l'application (A5 et A6) est conservé.

A1. Erreur : variante error (attendu : alert) A2. Avertissement (attendu : alert) A3. Succès (attendu : status) A4. Information (attendu : status) A5. Erreur avec role="status" écrit par l'auteur (attendu : status, il remplace le défaut) A6. Information avec role="alert" écrit par l'auteur (attendu : alert) A7. Erreur avec without-notification (attendu : aucun rôle, aucune annonce)

C. Modification d'une alerte déjà présente

Séquence suggérée : (1) Recréer l'alerte ; (2) Passer en error (le composant passe role à alert) ; (3) Poser role="status" comme le ferait une liaison de framework ; (4) Passer en info puis Passer en error : le role posé par l'application doit rester status ; (5) Retirer l'attribut role puis Passer en warning : le composant reprend la main (alert).
