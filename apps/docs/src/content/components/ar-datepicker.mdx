## Accessibilité

Le calendrier suit le pattern [APG Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/).

### Pris en charge automatiquement

- Navigation clavier complète dans la grille de jours (<WcagRef criterion="2.1.1" summary="Keyboard : toutes les fonctionnalités sont accessibles au clavier." />)
- Focus piégé dans le dialog calendrier lors de son ouverture, restitué à l'input à la fermeture (<WcagRef criterion="2.1.2" summary="No Keyboard Trap : le focus peut être déplacé hors du composant." />)
- Le slot `error` est enveloppé dans un `role="alert"` — annoncé automatiquement aux lecteurs d'écran (<WcagRef criterion="4.1.3" summary="Status Messages : les messages de statut doivent être annoncés aux technologies d'assistance sans déplacer le focus." />)
- `aria-disabled="true"` sur les jours hors plage et les jours désactivés (<WcagRef criterion="4.1.2" summary="Name, Role, Value : les états des éléments interactifs sont communiqués aux AT." />)
- Le hint par défaut donne un exemple de date formatée et, avec `min` ou `max`, la plage sélectionnable (<WcagRef criterion="3.3.2" summary="Labels or Instructions : des instructions sont fournies lorsque le contenu nécessite une saisie de l'utilisateur." />)

### À votre charge

- **Label** : toujours fournir un label via la prop `label` ou le slot `label`.
- **Hint** : pour un autre contenu que le hint par défaut, utiliser le slot `hint` (jamais `placeholder`, qui disparaît à la saisie). Il remplace le hint par défaut, exemple de date et plage `min`/`max` compris : à répéter si nécessaire.
- **Focus des jours** : l'indicateur de focus visible (<WcagRef criterion="2.4.7" summary="Focus Visible : le composant recevant le focus clavier doit être visuellement identifiable." />) est porté par `--ar-datepicker-day-focus-ring-color`/`-width`/`-offset`. `--ar-datepicker-day-focus-border-color` est cosmétique : le redéfinir n'affecte pas la garantie WCAG 2.4.7.

## Utilisation

### Largeur du champ de saisie

`--ar-datepicker-input-max-width` est calculé par défaut d'après la longueur de `format`, indépendamment de la largeur du hint. Si vous le surchargez, restez proche du contenu attendu dans le champ.

### Validation

Un contenu dans le slot `error` met le composant en erreur : l'état `ar-datepicker:state(has-error)::part(input)` permet de styler l'input (avant Chrome et Edge 125 : `ar-datepicker:--has-error::part(input)`). Le composant applique lui-même la bordure d'erreur : un thème qui fixe la couleur de bordure de `::part(input)` doit exclure cet état (`ar-datepicker:not(:state(has-error))::part(input)`), sinon sa règle l'emporte.

`min` et `max` valent aussi pour une saisie au clavier : hors plage, `valid` vaut `false` dans le `detail` des événements `ar-datepicker-input-complete` et `ar-datepicker-input-change`, et le champ porte `rangeUnderflow` ou `rangeOverflow` (`form.checkValidity()` échoue). `value` garde la date saisie.

`complete` et `valid` dans le `detail` de `ar-datepicker-input-complete` permettent de n'afficher l'erreur qu'une fois la saisie terminée :

```js
el.addEventListener('ar-datepicker-input-complete', ({ detail }) => {
    errorSlot.hidden = detail.valid;
});
```

### Dates désactivées

En complément de `min`/`max`, `isDateDisabled` couvre des règles arbitraires. Les jours concernés reçoivent `aria-disabled="true"` ; le hint par défaut ne les décrit pas, à préciser via le slot `hint` si nécessaire.

```js
el.isDateDisabled = (d) => d.getDay() === 0 || d.getDay() === 6; // week-ends
```

### Jours chargés à la demande

`ar-datepicker-view-change` est émis à l'ouverture et à chaque changement de mois. Posez `pending` le temps du chargement, puis réassignez `isDateDisabled` :

```js
datepicker.addEventListener('ar-datepicker-view-change', async ({ detail }) => {
    datepicker.pending = true;
    try {
        const unavailable = await loadUnavailableDays(detail.year, detail.month);
        datepicker.isDateDisabled = (d) => unavailable.has(d.toISOString().slice(0, 10));
    } finally {
        datepicker.pending = false;
    }
});
```

### Formulaires

`ar-datepicker` participe aux formulaires natifs (`name`, `required`, `readonly`, `disabled`, comme un champ natif) et expose l'API de validation standard (`checkValidity()`, `reportValidity()`, `validity`…).

- `form.reset()` ramène le champ à sa valeur initiale, texte de saisie compris, sans événement de valeur ; un panneau ouvert se ferme avec ses événements habituels.
- `setCustomValidity(message)` signale une erreur, par exemple venue du serveur. Comme sur un `<input>`, elle persiste jusqu'à `setCustomValidity('')`. Le slot `error` reste l'affichage du message dans la page.
- Seuls `:invalid` et `:valid` s'appliquent nativement. À la place de `:required`, `:optional`, `:user-invalid` et `:user-valid`, le composant expose `:state(required)`, `:state(optional)`, `:state(user-invalid)` et `:state(user-valid)`. Comme en natif, les deux derniers n'apparaissent qu'après une interaction de l'utilisateur, une tentative de soumission ou `reportValidity()`.

```css
ar-datepicker:state(user-invalid)::part(input) {
    border-color: var(--couleur-erreur);
}
```

### Intégration masque de saisie

Le getter `inputElement` expose l'`<input>` interne pour y brancher une bibliothèque de masque comme IMask :

```js
import IMask from 'imask';
const picker = document.querySelector('ar-datepicker');
IMask(picker.inputElement, { mask: Date });
```

### Libellés des boutons « Aujourd'hui » et « Fermer »

Ces textes suivent l'attribut `lang` (cf. [Traductions](/getting-started/traductions)). Les slots `today-label` / `close-label` les remplacent par un contenu plus riche ; le texte traduit reste la source de l'`aria-label` du `<button>`, même si le slot ne contient qu'une icône :

```html
<ar-datepicker lang="en">
    <span slot="close-label" aria-hidden="true">✕</span>
</ar-datepicker>
```
