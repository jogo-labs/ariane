## Accessibilité

Le calendrier suit le pattern [APG Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/).

### Pris en charge automatiquement

- Navigation clavier complète dans la grille de jours (<WcagRef criterion="2.1.1" summary="Keyboard : toutes les fonctionnalités sont accessibles au clavier." />)
- Focus piégé dans le dialog calendrier lors de son ouverture, restitué à l'input à la fermeture (<WcagRef criterion="2.1.2" summary="No Keyboard Trap : le focus peut être déplacé hors du composant." />)
- Le slot `error` est relié à l'input par `aria-describedby` : le message est lu quand le champ reçoit le focus (<WcagRef criterion="1.3.1" summary="Info and Relationships : les informations et relations présentées visuellement sont aussi disponibles par programme." />)
- `aria-invalid="true"` sur l'input quand le slot `error` est rempli ou quand le champ est invalide après une interaction, comme un champ natif
- `aria-disabled="true"` sur les jours hors plage et les jours désactivés (<WcagRef criterion="4.1.2" summary="Name, Role, Value : les états des éléments interactifs sont communiqués aux AT." />)
- Le hint par défaut donne un exemple de date formatée et, avec `min` ou `max`, la plage sélectionnable (<WcagRef criterion="3.3.2" summary="Labels or Instructions : des instructions sont fournies lorsque le contenu nécessite une saisie de l'utilisateur." />)

### À votre charge

- **Label** : toujours fournir un label via la prop `label` ou le slot `label`.
- **Hint** : pour un autre contenu que le hint par défaut, utiliser le slot `hint` (jamais `placeholder`, qui disparaît à la saisie). Il remplace le hint par défaut, exemple de date et plage `min`/`max` compris : à répéter si nécessaire.
- **Annonce des erreurs** : le composant n'annonce pas un message d'erreur à son apparition. À la soumission d'un formulaire, affichez un récapitulatif des erreurs et placez le focus dessus ou sur le premier champ en erreur (voir [Formulaires](/getting-started/controles-de-formulaire#annoncer)).
- **Focus des jours** : l'indicateur de focus visible (<WcagRef criterion="2.4.7" summary="Focus Visible : le composant recevant le focus clavier doit être visuellement identifiable." />) est porté par `--ar-datepicker-day-focus-ring-color`/`-width`/`-offset`. `--ar-datepicker-day-focus-border-color` est cosmétique : le redéfinir n'affecte pas la garantie WCAG 2.4.7.

## Utilisation

### Largeur du champ de saisie

`--ar-datepicker-input-max-width` est calculé par défaut d'après la longueur de `format`, indépendamment de la largeur du hint. Si vous le surchargez, restez proche du contenu attendu dans le champ.

### Formulaires

`ar-datepicker` se comporte comme un champ de formulaire natif : soumission, validation, états et réinitialisation sont décrits dans la page [Formulaires](/getting-started/controles-de-formulaire). Propre au datepicker, `form.reset()` ramène aussi le texte de saisie à son état initial, et un panneau ouvert se ferme avec ses événements habituels (`ar-datepicker-hide`, `ar-datepicker-hidden`).

### Intégration masque de saisie

Le getter `inputElement` expose l'`<input>` interne pour y brancher une bibliothèque de masque comme IMask :

```js
import IMask from 'imask';
const picker = document.querySelector('ar-datepicker');
IMask(picker.inputElement, { mask: Date });
```

### Libellés des boutons « Aujourd'hui » et « Fermer »

Ces textes suivent l'attribut `lang` (cf. [Traductions](/getting-started/traductions)). Les slots `today-label` / `close-label` les remplacent par un contenu plus riche ; le texte traduit reste la source de l'`aria-label` du `<button>`, même si le slot ne contient qu'une icône :

```html
<ar-datepicker lang="en">
    <span slot="close-label" aria-hidden="true">✕</span>
</ar-datepicker>
```
